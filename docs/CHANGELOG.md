## [v3.21] — 2026-06-22 — P0 из council-аудита: LLM больше не закрывает задачи сам
По итогам `/council` (брутальная критика бота тремя моделями) главный риск — **доверие к данным**: LLM-судья автономно закрывал задачи (корень кейса @tutor_lena). Теперь авто-закрытие по переписке — это **предложение, а не действие**. smoke 42/42, DONE-судья не менялся (eval не требовался).
### Изменено
- **`auto_close_tasks` больше не закрывает.** LLM-судья (`_check_tasks_done_batch`) по-прежнему детектирует вероятно выполненные задачи, но вместо закрытия шлёт владельцу карточку **«🤔 Похоже, выполнено — Закрыть? [✅ Да, закрыть][↩️ Открыта]»**. Реальное закрытие — только по кнопке ✅ (`td:` → `cb_done`). Guard `timeclose:{id}` (раз/сутки на задачу), ❓-заготовки пропускаются.
- **Новый колбэк `keepopen:` («↩️ Открыта»)** — задача остаётся открытой; повторные предложения по ней глушатся на **7 дней** (`closesuppress:{id}` в settings_kv) — уважаем «нет» владельца.
- **Намеренно НЕ тронуто** (кандидаты на P0.5): авто-переоткрытие (безопасное направление — не теряет данные) и `time_settle_tasks` (детерминированное закрытие по времени, уже с кнопками для неоднозначных случаев).
### Контекст
Первый из приоритетов council-аудита. Дальше на очереди: P1 — один источник истины (Todoist=задачи / одно из Notion·Obsidian=CRM / GCal=встречи); P2 — заморозка фич; P3 — RAG→FTS5.

## [v3.20] — 2026-06-21 — Фикс: две задачи-урока не создавались (@tutor_lena)
Разбор по жалобе владельца «почему не создались две задачи с уроками английского». Логи дали точную причину: бот **всё извлёк правильно** (Ср 17:00 / Пт 19:00), но обе задачи погибли в одном settle-проходе из-за двух багов. smoke 42/42, EXTRACT/classifier/DONE-промпт не менялись (eval не требовался).
### Корень (по логам 21.06)
1. В 15:19 (пока времён не было — «среда и пятница после 16») создана расплывчатая `❓ Урок английского` (due=None). В 15:48 пришли «Ср 17 / Пт 19». В 15:59 settle: сначала `auto_close` **закрыл** `❓`-заготовку, затем извлёк 2 датированные урока — и обе **отбраковались как дубль** только что закрытой заготовки.
### Исправлено
- **`auto_close` не закрывает `❓`-задачи** (`core/actions.py`) — заготовка «дело согласовано, время не уточнено» больше не гибнет по переписке-согласованию до конкретизации.
- **Дедуп: датированная задача ≠ дубль бездатной заготовки** (`db.task_exists_recently`) — раньше guard «разные дни» не срабатывал, когда у заготовки даты нет → конкретные «Ср/Пт» гасились о `❓`. Теперь датированный кандидат против бездатной похожей = конкретизация, не дубль.
- **Refinement не сливает разные дни** (`core/actions.py`) — при конкретизации бездатной заготовки в несколько датированных задач снимок даты обновляется в проходе, чтобы второй урок (другой день) не слился с первым.
- +1 async-тест на `task_exists_recently` (датированная vs бездатная). smoke 41→42.
### Данные (с подтверждением)
Созданы две пропавшие задачи: «Урок английского с @tutor_lena» на **ср 2026-06-24 17:00** (#95) и **пт 2026-06-26 19:00** (#96) — Todoist+Notion+Calendar.

## [v3.19] — 2026-06-20 — Добиты 6 отложенных пунктов аудита
Закрыт хвост бэклога аудита (аккуратно, с тестами). smoke 41/41 (+2 теста), EXTRACT/classifier/DONE/PROFILE не менялись (eval не требовался). Прод 🟢, индекс-миграция проверена.
### Исправлено / Добавлено
- **Шум self-канала** — пересланный в личку пост/док больше не «взрывается» в N задач: при форварде карточка capture капится до 1 задачи (кейс «18 задач из одного changelog»); остальное и так в инбоксе/ссылках. (`_do_capture`)
- **Backstop `UNIQUE notion_page_id`** — партиальный уникальный индекс `idx_task_notion_uniq` (NULL допускает множество) → `INSERT OR IGNORE` теперь дедупит и по Notion-странице (раньше при partial-создании с NULL todoist могли двоиться). На проде дублей нет (проверено), миграция guarded. Применена и проверена на проде.

- **FTS-фолбэк `intent=ask`** — при выключенном RAG (дефолт) бот больше не отвечает глухим отказом, а ищет по ключевым словам в переписке (`search_conversations`, как `/find`) и отвечает по найденному. (`_fts_fallback_hits`)
- **Персист capture-карточки** — pending-задача из лички переживает рестарт/деплой: дублируется в `settings_kv` (`cap:{token}`, TTL 6ч), `cb_capture` восстанавливает из неё, если in-memory очистилось. Больше не «Карточка устарела» после каждого деплоя.
- **Календарь при авто-закрытии** — `delete_calendar_event` теперь зовётся при авто-закрытии задачи (по переписке `auto_close_tasks` и по времени `time_settle_tasks`) — гасит осиротевшие события с попап-напоминаниями (раньше чистил только ручной 🗑).

### Добавлено

- 🔗 **`reconcile_commitment_tasks`** (зовётся из `enrich_profile`): enrich по-прежнему ловит обещания ШИРОКО (включая мягкие) → реконсилятор **заводит задачей-обещанием** те, которых ещё нет среди открытых, и которые **не закрывались недавно** (14 дн — иначе воскреснет снятое). - **Итог — единый принцип:** обещание = закрываемая задача; охват широкий (enrich+EXTRACT создают), протухание невозможно (всё закрываемо), воскрешения нет (guard по недавно-закрытым). Дры-ран на проде подтвердил: существующие открытые пропускаются, новое создаётся, недавно-закрытые не воскрешают.
- Текстовое `commitments` остаётся как **детект-буфер enrich** (его вход) + контекст памяти; источник правды для «Ты обещал»/`/обещания` — открытые задачи-обещания.

## [v3.13] — 2026-06-17 — Обещания = задачи (живые, закрываемые) — конец протуханию «Ты обещал»
### Изменено / Добавлено
Корень протухания «⚠️ Ты обещал»: дайджест читал **свободный текст** `contact_profiles.commitments` (его ведёт enrich) — а тот чистится только при наличии доказательства выполнения **в переписке**; офлайн-выполненные обещания (плиту починил, вещь привёз) виснут вечно. ## [v1.0] — 2026-06-06
Первая боевая версия. Собран с нуля.

### Классификация
- Правила (regex, бесплатно) + Claude Haiku fallback
- Категории: SPAM / BUSINESS / FRIEND / UNCLEAR

### Извлечение задач
- LLM находит action items с датой/временем (`YYYY-MM-DDTHH:MM`)
- Контекст 10 последних сообщений, обновление существующих задач, дедупликация

### Интеграции
- **Todoist** — проект «Telegram Входящие» + разделы (Бизнес/Встречи/Проверить/Личное) + метки
- **Notion** — база задач (7 видов) + база контактов + Dashboard
- **Google Calendar** — события при наличии времени (сервис-аккаунт), напоминания 60+10 мин
- **Vault** — профиль контакта (кто/зачем/темы/резюме) → Obsidian + Notion
- Двусторонняя синхронизация Todoist↔Notion + импорт ручных задач

### Медиа
- 🎙 Голос → faster-whisper (локально, бесплатно, лимит 2 ядра / 5 мин)
- 📸 Фото → Claude Vision (лимит 30/день)
- 📎 Документы → PDF / DOCX / TXT

### Автоматизация
- Дайджест 09:00, напоминания 20:00, недельный отчёт, дожимание >2 дней
- Детектор срочности → мгновенный push
- Авто-ответы (настраиваемые `/setreply`)
- Инлайн-кнопки: [Выполнено][Удалить], [Создать][Игнор], [Ответил]

### Команды
`/start` `/health` `/stats` `/last` `/about` `/find` `/setreply` `/correct` `/mode` `/friend` `/unfriend` `/whitelist`

### Надёжность
- WAL-режим, бэкапы (`VACUUM INTO`, 7 копий), очистка vault 6 мес
- Мониторинг аптайма (cron + авто-рестарт + алерт), лимиты (бюджет/фото/rate)
