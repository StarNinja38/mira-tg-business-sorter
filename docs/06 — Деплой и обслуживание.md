## Синхронизация Vault (на Mac → iPhone/iPad)

launchd-агент `~/Library/LaunchAgents/com.tgsorter.vaultsync.plist`, каждые 15 мин.
Скрипт: `~/.tgsorter/sync_vault.py`. Логи: `/tmp/tg_vault_sync.log` (+ `_error.log`).

**Схема:** агент тянет `bot.db` (+`-wal`) с сервера → пишет markdown в волт → **iCloud** синкает на Mac/iPhone/iPad.

| Параметр | Значение |
|----------|----------|
| Волт | `~/Library/Mobile Documents/iCloud~md~obsidian/Documents/Claude(Second Brain)` (контейнер Obsidian iCloud) |
| Папка TG | `…/Claude(Second Brain)/Telegram/` (реальная папка, в `.gitignore` Second Brain) |
| Python агента | **`/opt/homebrew/bin/python3`** (Homebrew) — у него FDA берётся; системный CLT-python НЕ берёт (баг TCC) |
| FDA | выдан `…/python@3.14/.../Resources/Python.app` в Настройки → Конфиденциальность → Полный доступ к диску |

```bash
# Принудительный запуск синхронизации
launchctl kickstart -k gui/$(id -u)/com.tgsorter.vaultsync

# Перезагрузить агент после правки plist
launchctl bootout gui/$(id -u)/com.tgsorter.vaultsync
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.tgsorter.vaultsync.plist

# Проверить логи (ошибок доступа быть не должно)
cat /tmp/tg_vault_sync.log; grep -i "not permitted" /tmp/tg_vault_sync_error.log
```

> [!warning] Если синк перестал писать («Operation not permitted»)
> Проверь FDA для Homebrew `Python.app`. После обновления Homebrew python (смена версии в пути `python@3.x`) — выдай FDA заново на новый `Python.app`.
> Бэкапы пути: `obsidian.json.bak`, `~/TelegramVault` (старый), git на GitHub.

## Админ-CLI `scripts/admin_ops.py` (v3.5.1)

Закрытый набор операций для запуска по ssh (скрипт сам делает chdir в `/opt/tg-business-sorter`):
```bash
P=/opt/tg-business-sorter/venv/bin/python
S=/opt/tg-business-sorter/scripts/admin_ops.py
ssh sn-ams $P $S read @username     # чтение памяти контакта (read-only)
ssh sn-ams $P $S health             # статус сервиса + ошибки за 24ч
ssh sn-ams $P $S logs 30            # последние 30 строк журнала
# ПРАВКИ (меняют прод-БД — запускать как tgsorter, с подтверждением):
ssh sn-ams sudo -u tgsorter $P $S setname @user Имя
ssh sn-ams sudo -u tgsorter $P $S addfact @user текст
ssh sn-ams sudo -u tgsorter $P $S fixrole @user роль
ssh sn-ams sudo -u tgsorter $P $S contact_memory        # пересобрать /me владельца
ssh sn-ams sudo -u tgsorter $P $S avatars        # сверить аватары с Telegram, обновить сменившиеся
```

**Авто-аватары:** ставятся при первом фото от контакта (`getUserProfilePhotos`) и **сверяются раз в день (04:00)** по `file_unique_id` — при смене аватара памяти обновляется (Telegram + vault; Notion ретайрнут). Источник фото в `photo_src`: `avatar` (авто, обновляется) / `manual` (`/setphoto`) / `confirmed` (подтверждённое присланное) — последние два авто-рефреш **не перетирает**.

### Модель прав Claude Code (`.claude/settings.local.json`)
- **Без подтверждения:** `admin_ops.py read|health|logs` + `rsync`/`scp` (чтение/диагностика/деплой).
- **С подтверждением владельца:** все правки (`setname/addfact/fixrole/contact_memory`, скрипты `/tmp`), рестарт, произвольный `ssh`.
- Allow-правила узкие (read-подкоманды по точному префиксу), не blanket-root. Расширять права может только владелец (Claude сам себе — нет).

## Оптимизация токенов Claude Code (дев-сессии)
Разведка инструментов (2026-06-15) → вывод: **стороннее не ставим**, оптимизация уже закрыта безопасной связкой.

**Что работает (3 слоя):**
1. **RTK (Rust Token Killer)** — хук переписывает дев-команды (git/чтения/поиск), 60–90% экономии.
2. **1M-контекст** (`/model …[1m]`) — сессия длиннее, реже упор в лимит.
3. **Правила гигиены** в `~/.claude/CLAUDE.md` (раздел «Token hygiene»): не перечитывать файлы / читать диапазоном; фильтровать большие выводы (grep/tail); по фоновым ssh ждать уведомления, не опрашивать пустой вывод; точечный grep.

**Почему НЕ ставим сторонние плагины** (Context Mode / token-optimizer-mcp / claude-context-optimizer / Lean):
- дублируют RTK (тот же перехват/сжатие) — выигрыша поверх почти нет;
- лезут хуками/сабпроцессами в агент, у которого **SSH к проду + ключи** → риск ради нулевой добавки;
- Lean (роутинг по моделям) конфликтует с «всегда Opus 4.8».
- Принцип: токены резать **поведением и текстом** (правила, точечные чтения, фильтры), а не сторонним кодом в прод-связанном Claude Code.

Детали разведки — в памяти проекта (`token-optimization-tools-verdict.md`). Это разовая настройка, поддерживать не нужно.
